# ORBITAL — AI Mission Atlas

> **"See what humanity is doing in space."**

An AI-powered interactive catalog of active human space missions across Earth, Moon, and Mars.

## Quick Start

```bash
cd orbital
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000)

---

## Features

- **Interactive 3D Space Visualization** — Earth, Moon, and Mars with live mission dots, orbits, and trajectories rendered with Three.js / React Three Fiber
- **Mission Catalog** — 14 missions seeded from real public data, fully filterable by destination and status
- **AI Space Analyst** — Ask questions about any mission; powered by a provider-agnostic AI layer (IBM watsonx / Granite or mock by default)
- **Mission Detail Pages** — Full timelines, spacecraft specs, imagery, and mission events
- **Risk Analysis** — Deterministic orbital risk analysis across the tracked fleet, including composite risk scoring, TCA (Time of Closest Approach), miss distance, relative velocity, risk severity classification (LOW / MODERATE / HIGH / CRITICAL), and data-quality / provenance indicators per spacecraft pair
- **Data Provenance** — Every data point labeled OBSERVED / DERIVED / AI / ESTIMATED
- **Mission Pulse** — At-a-glance global status across Earth, Moon, and Mars
- **Mission Timeline** — Chronological view of all mission events
- **Global Search** — Search by mission name, spacecraft, agency, or NORAD ID

> **Risk Analysis disclaimer:** The risk scores are deterministic, simplified orbital-geometry indicators intended for situational awareness and demonstration. They are **not** collision probabilities, operational conjunction assessments, or substitutes for authoritative space traffic management data.

## Data Integrity

All data points are labeled with their provenance:

| Label | Meaning |
|-------|---------|
| **OBSERVED** | Directly sourced from a public authoritative database |
| **DERIVED** | Mathematically calculated from public orbital data |
| **AI** | Generated by the AI layer from available mission context |
| **ESTIMATED** | Approximate values based on known mission parameters |

**ORBITAL does not fabricate telemetry, spacecraft health data, or real-time positions.**

For Risk Analysis specifically: risk scores are computed deterministically from simplified orbital geometry and constant-velocity trajectory analysis. They are **not** collision probabilities and are **not** operational conjunction assessments. Pairs that rely on simplified orbital elements are labeled **ESTIMATED** in the data-quality field.

## AI Integration

ORBITAL uses a provider-agnostic `AIProvider` interface defined in [`lib/ai.ts`](./lib/ai.ts):

```typescript
interface AIProvider {
  generateResponse(
    messages: AIMessage[],
    context: AIContext,
    systemPrompt: string
  ): Promise<string>;
}
```

The active provider is selected at runtime via the `AI_PROVIDER` environment variable:

| Value | Behaviour |
|-------|-----------|
| `mock` | Deterministic local responses — no external calls (default) |
| `watsonx` | IBM watsonx.ai / Granite via the `/ml/v1/text/chat` REST API |

When `AI_PROVIDER=watsonx`, the server-side layer exchanges the `AI_API_KEY` for an IAM bearer token and calls the configured Granite model. No credentials are ever sent to the browser.

The AI layer also supports orbital risk context: when a user triggers **Analyze with AI** on a conjunction, the risk entry is passed as structured grounding data so the model responds with mission-specific, factually-grounded explanations rather than generic answers.

## Environment Variables

Copy `.env.example` to `.env.local` and fill in your values. **Never commit `.env.local` — it is already in `.gitignore`.**

```env
# NASA public API (get a free key at https://api.nasa.gov/)
NASA_API_KEY=DEMO_KEY

# Optional database connection
DATABASE_URL=

# AI provider selection: mock | watsonx
AI_PROVIDER=mock

# IBM Cloud API key — server-side only, required when AI_PROVIDER=watsonx
AI_API_KEY=

# IBM watsonx.ai project and endpoint — required when AI_PROVIDER=watsonx
WATSONX_PROJECT_ID=
WATSONX_URL=
WATSONX_MODEL_ID=
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

## Demo Flow

1. Open ORBITAL and explore the 3D mission visualization — Earth, Moon, and Mars with active mission markers.
2. Browse the **Mission Catalog** and select **Artemis II** or another mission to view its detail page.
3. Open the **AI Analyst** panel and ask a mission-specific question such as _"What is Artemis II doing?"_
4. Open **Risk Analysis** and inspect the conjunction table — review risk severity, TCA, miss distance, relative velocity, and data-provenance labels for each spacecraft pair.
5. Select **Analyze with AI** on a risk entry to get a grounded, mission-specific explanation.
6. Navigate to **Mars**, select **Perseverance**, and explore rover imagery and the mission timeline.
7. Use the **Timeline** and **Global Search** to navigate across all missions.
8. Open **Data Sources** to review transparent data provenance for every displayed value.

## IBM Challenge Notes

- **AI Integration:** IBM watsonx / Granite is the primary production AI backend. Enable it by setting `AI_PROVIDER=watsonx` and supplying credentials in `.env.local`.
- **Data Integrity:** All displayed values carry explicit provenance labels. ORBITAL never fabricates telemetry or operational data.
- **Risk Analysis:** A fully implemented, deterministic orbital risk engine (`lib/risk.ts`, `app/api/risk/route.ts`, `components/RiskHUD.tsx`) demonstrates structured spatial reasoning and data-quality transparency — not simulated collision prediction.
- **Provider-Agnostic AI Layer:** The `AIProvider` interface makes it straightforward to swap or extend AI backends without changing application logic.
